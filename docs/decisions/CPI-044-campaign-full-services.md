### Offline purchase delivery and store wiring · 12 November 2026

The current main artwork/performance source `218b973` was merged into this service branch without copying superseded UI files. The service-only Campaign store now uses the existing native billing/verified-receipt flow, provider-localized prices, cancellation/pending/error states and restore controls. Free claims are explicitly guarded by the offline test-build flag. Public production remains on its existing disabled-by-default profile; this work does not publish the Campaign shop.

New shields/season-change/permanent grants are followed by an offline-inventory transfer. `offline_supply_allocations` debits the server wallet and stores a bounded, immutable resource receipt in the same transaction. The owner can retry the same operation with the same quantities; another owner, a changed request, overspending and invalid amounts are rejected. Before acknowledging a transfer, the client saves both additions and the receipt ID inside the existing Campaign envelope. Repeating an unacknowledged receipt does not add resources twice. Confirmed receipts are removed locally only after server acknowledgement. Pending allocations are recoverable after a disconnect, app close or local write failure. No network call is required for each tile or supply use; the existing atomic Infinity checkpoint/inventory write remains the spending authority for that device. These are local assisted runs, not official ranked results. Ranked wallet debits and historical rules are unchanged.

This is **device-bound consumable stock**, not cloud synchronization: after a transfer has been acknowledged, deleting local app data loses its unused local stock. The store explains that supplies stay on this device; permanent purchases restore through the account. Uncollected wallet balances and unacknowledged transfers remain on the server. The client respects the existing 10,000-per-resource capacity and leaves excess funds uncollected. This tradeoff keeps collected supplies usable offline and must be included in physical-device acceptance and support planning. Do not advertise consumable cross-device restoration. Offline local progress can be modified on a compromised device and must never authorize money, real purchases or official scores.

Billing aliases select separate local Campaign/inventory namespaces. The remembered alias is a noncredential pointer for offline play, never API authorization. Explicit sign-out/account rejection clears the pointer; account changes cannot fund the next account's inventory. Verified wallet refresh removes refunded/unowned paid cosmetics while preserving earned Campaign artwork. First account entry seeds guest-earned Campaign progress, without importing another private inventory or the separate free-claim QA namespace. Device music/preferences, tutorial and local journal/record metadata retain their common device storage.

The additive migration supplies a separately paginated own-data export for transfers, with server-only RLS/grants and no raw provider proofs or billing aliases in exported rows. Account deletion retains the existing anonymous wallet linkage needed for financial replay barriers; ownership is not reassigned. Tests cover replay, refunds, cross-account attempts, failed writes, replay after restart and malformed grants. Full validation and hosted activation evidence must be appended after those steps run; source preparation alone is not checkout acceptance.
